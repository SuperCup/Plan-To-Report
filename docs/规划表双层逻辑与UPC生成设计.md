## 二、规划表结构（双层）

```
┌─ 活动区：D 列=字段名行，E…S 列=各活动 ─────────────────────┐
│  D2:D9  活动类型、活动机制、机制力度、活动时间…（仅映射行）   │
│  E2:E9  列 E 的第 1 个活动参数                              │
├─ 商品区：C=子品牌，D=规格，E11:末行=参与矩阵 ────────────────┤
│  参与形态：√ | 单元格写口味 | 单元格写多口味/多行规格组合      │
└──────────────────────────────────────────────────────────────┘
```

## 三、新的执行流程（替代「执行顺序」）

规划表 Sheet 指定为「规划表」后，界面切换为 **四步向导**，不再显示「逐行/逐列」：

```mermaid
flowchart LR
    S1[① 框选区域] --> S2[② 映射活动字段行]
    S2 --> S3[③ 勾选活动列]
    S3 --> S4[④ 确认商品区并执行]
```

### 步骤 ① 框选区域

- 在预览区点击 **起始**（如 `D2`）、**结束**（商品矩阵末行末列）。
- 自动识别：字段名列（D）、首个活动列（E）、商品区起始行（含「规格」表头行下一行）。

### 步骤 ② 映射活动字段行

- 列出 D 列在活动区内的**非空行**（合并拆分后取末行文本）。
- 用户将每行绑定到逻辑字段：`活动类型`、`活动机制`、`机制力度`、`活动时间`、`活动区域/渠道`、`优惠券类型`、`预算分配`、`机制说明`（空白行首内容）等。
- **仅绑定行参与解析**，空行跳过。

### 步骤 ③ 勾选活动列（对应确认 #1）

- 预览区 **活动列标题条**：对 E、F、G… 每列显示列号 + 首字段摘要（如「单品牌机制 / 满16-2」）。
- 用户 **勾选需要生成的列**；未勾选列不产出汇总行与 UPC 行。
- 支持全选 / 反选 / 仅选有机制列。

### 步骤 ④ 确认商品区并执行

- 确认：`商品区起始行`、`子品牌列 C`、`规格列 D`。
- 上传 **商品匹配逻辑**、**商品清单**（必填）。
- 点击「执行转换」→ 活动汇总表 + 活动对应 UPC 表 + 异常清单。

**其他 Sheet 类型**（商品清单、预算表等）：仍可用简单模式「选区 + 首行表头」导入，不走上述向导。

## 四、活动解析

### 4.1 读取活动字段

对每个**已勾选**活动列 `col`：

```
FOR (field_key -> row) IN user_field_mapping:
    activity[field_key] = cell(row, col)
```

空列跳过；`活动机制` 与 `活动类型` 皆空则视为无效列。

### 4.2 活动机制拆分（确认 #8）

若 `活动机制` 匹配 `①…②…` 或多段「满 X-Y」：

```
segments = split_mechanism(活动机制)   # 如 ["满16-2", "满31-5"]
FOR seg IN segments:
    activity_copy = activity
    activity_copy["活动机制"] = seg
    activity_copy["_split_index"] = i
    EMIT activity_copy
```

- 两条活动 **共享同一列 `col` 的商品矩阵**（勾选不复制列）。
- 汇总表输出 2 行；UPC 表每行带相同列勾选结果，备注/机制字段区分段。

### 4.3 活动备注拼接（确认 #9）

写入活动汇总表 **备注**（或内部 `_remark`），规则：

```
备注 = 活动类型 + 活动机制 + 机制力度 + 活动时间 + 活动区域/渠道
     + 优惠券类型 + 预算分配 + 机制说明
```

- 各段用 `+` 连接，空段跳过。
- **机制说明**：活动区中，合并拆分后「空白行」的**首行**单元格内容（例：`全国神价活动`）。
- 若机制已拆分，备注中的机制段用当前拆分后的单段机制。

**自定义编码**（UPC 表关联）：可与备注相同，或备注 + `|列号`；开发时与 UPC 表字段统一。

## 五、商品区解析

### 5.1 子品牌（仅 C 列，确认 #3）

纵向合并拆分后 **仅末行有值**。解析商品行时使用 **forward fill**：

```
brand(r) = last_non_empty(C, product_row_start .. r)
```

匹配逻辑表时，用 `brand` 对齐 **商品匹配逻辑.品牌** 列。

### 5.2 规格列 D

每行 `spec = cell(r, D)`，非空才视为有效商品行。

### 5.3 参与判定（确认 #4）— 三种模式

对活动列 `col`、商品行 `r`，读取 `cell(r, col)`：

| 模式 | 判定 | 处理 |
|------|------|------|
| **A. 标准勾选** | 值为 `√` / `✓` 等 | 参与整行：`品牌=C继承, 规格=D` |
| **B. 单元格写口味/规格** | 非空且非勾选符 | 见图 1：表头合并写「番茄/辣番茄」，单元格写 `番茄` → 仅该口味 |
| **C. 多口味合写** | 含 `/`、换行、顿号 | 见图 2：`藤/麻/泡/…` 多行 → 拆成多个口味 token，再与 C 列子品牌下口味行匹配 |

**模式 B/C 的拆分与替换（拆合并单元格时）：**

1. **表头口味合并**（跨多行的 D 或活动列表头）：拆分时将合并区原文写入**末行**；解析时向上读取末行表头作为「可选口味池」。
2. **合写口味**：`番茄/辣番茄` → `["番茄","辣番茄"]`；`藤/麻/泡` → 通过**口味别名表**映射到 C 列完整名（如 `藤`→`藤椒牛肉`）。
3. **包装分行**：活动列单元格多行文本，第一行口味列表、下面各行规格 → 解析为 `(口味, 规格)` 组合，仅选中列出的口味×规格。
4. **文字替换**：配置 `口味别名.json` 或内置缩写表；匹配逻辑选品串中的名称优先，规划表缩写次之。

```
parse_participation(cell, brand, spec, flavor_rows_under_brand):
    IF is_checkmark(cell): RETURN [(brand, spec, ALL_FLAVORS_IN_ROW)]
    IF cell is flavor_only: RETURN [(brand, spec, resolve_flavor(cell))]
    IF cell has slashes/newlines: RETURN expand_flavor_tokens(cell, brand, spec)
```

### 5.4 与商品行的口味行关系（图 2）

当 C 列同一子品牌下有多行（每行一个口味名 + D 列规格）：

- 活动列写的是「缩写口味集合」时，只勾选 **C 列口味名能匹配上 token 的行** + 对应 D 规格。
- 活动列是 `√` 时，该 `spec` 行下**所有口味行**均参与（或仅当前行，按行粒度：一行 C+D 为一条逻辑商品键）。

> **实现默认**：以 **「每个商品行 (C 继承品牌 + D 规格 + 当前行 C 若不为空则为本行口味)」** 为粒度；`√` 表示该行参与；单元格写口味则表示仅该口味行（需 C 列同行或能匹配到口味行）。

## 六、商品匹配逻辑表（图 3）

### 6.1 表结构

| 列 | 含义 |
|----|------|
| A（分类） | 基量 / 增量 / 培育 — 可选，用于分组展示 |
| **品牌** | 对应规划表 C 列子品牌，如「红烧牛肉」「番茄/辣番茄」 |
| **规格** | 对应规划表 D 列，如「开心桶」「经典袋五包」 |
| **选品逻辑** | 查询商品清单的条件串 |

### 6.2 选品逻辑串格式（解析规则）

典型一行：

```
品牌名称：红烧品牌--口味名称：红烧牛肉--规格名称：开心桶、965桶
```

解析步骤：

1. 按 `--` 分段。
2. 每段 `字段名：值列表`，字段名 ∈ {`品牌名称`, `口味名称`, `规格名称`}。
3. 值列表按 `、` 拆分多个候选。
4. 括号内红色说明（如「整箱售卖…不要」）记入 **排除规则**，查表后过滤（二期可细化）。

匹配键：用规划表参与行的 `(C子品牌, D规格)` 在逻辑表中找 **品牌+规格** 完全匹配行；若单元格指定了口味，则把口味并入查询条件（覆盖或收窄逻辑串中的口味名称）。

### 6.3 查商品清单（图 4，确认 #6、#7）

商品清单固定列（查询用）：

| 列名 | 用途 |
|------|------|
| 商品条形码 | 输出 UPC |
| 品牌名称 | 条件 |
| 口味名称 | 条件 |
| 规格名称 | 条件 |
| 标品名称、建议零售价、状态… | 可选带出 |

```
conditions = parse_selection_logic(选品逻辑行)
matches = product_list.filter(品牌名称 in conditions.品牌 AND
                               口味名称 in conditions.口味 AND
                               规格名称 in conditions.规格)
FOR each row IN matches:
    EMIT upc_row(activity, row.商品条形码, ...)
```

- **多条全部输出**（确认 #7）。
- 0 条 → 异常清单 warning，带活动列、品牌、规格、选品逻辑原文。

## 七、输出表

### 7.1 活动汇总表

- 仅 **用户勾选的活动列** × **机制拆分后的活动段**。
- 字段映射沿用已定规则（方案名称空、活动=活动机制、券名称=康师傅+优惠券类型…）。
- **备注** = 第四节拼接规则。

### 7.2 活动对应 UPC 表

每行：`自定义编码/备注关联字段` + 活动关键信息 + C 子品牌 + D 规格 + 匹配到的口味 + UPC + 商品清单其他列。

同一活动 × 同一勾选可对应 **多行 UPC**。

## 十二、小结

规划表按 **列式活动 + 矩阵商品** 解析；用户 **勾选列**、**映射字段行** 替代执行顺序；商品参与支持 **√、口味、合写** 三种形态；经 **商品匹配逻辑 → 商品清单** 展开全部 UPC；机制拆分 **共享列勾选**；备注按 **+** 拼接含机制说明。可按 P0→P1 开始编码。
